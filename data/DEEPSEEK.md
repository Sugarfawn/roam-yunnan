# DeepSeek 申请与本地接入

当前页面已更新为“先选地点→补充偏好→AI安排”，并对第一次不合格结果自动校正一次。道路距离与交通改由高德接口独立查询，模型不编造这些数字。当前流程和测试见 [PLANNING-EXPERIENCE.md](PLANNING-EXPERIENCE.md)，以下保留接入与配置说明。

## 你需要做的三步

1. 打开 https://platform.deepseek.com/ ，注册或登录。进入“API keys”，创建一个用于“漫游云南”的 API key，并保存平台生成的密钥。API调用的额度、余额与费用以该开放平台为准。
2. 在项目根目录打开 `.env.local`，把密钥填写在 `DEEPSEEK_API_KEY=` 后面。不要填到网页HTML、浏览器脚本或高德地图配置中。示例：`DEEPSEEK_API_KEY=你申请的密钥`。本文件不记录真实密钥；`.env.local` 已加入Git忽略。
3. 在项目目录运行 `node server.cjs`，打开 http://127.0.0.1:4174/ 。Node.js 20以上即可，无需安装生产依赖。当前电脑原4173预览也能通过本地4174后端调用AI。

`.env.local` 每次请求都会重新读取。配置后刷新规划页；页面应显示“已读取 DeepSeek 配置”。这个状态表示后端已读到密钥，并不代表账号额度或密钥有效性已被真实调用验证。正式生成时会按实际接口响应处理。

## 页面使用

只保留“生成我的路线”一个入口。选择地区、天数、偏好、节奏、交通、景点及酒店餐厅，可填写额外旅行期待；点击后由DeepSeek生成每日安排，服务器和浏览器先后进行验证。没有密钥、接口错误、余额不足、超时、取消、返回空内容或校验失败，都不会伪装为AI成功，也不会覆盖已保存行程。

旧版保存的行程仍能查看，会标注为历史参考行程。演示A/B仅预填偏好，点击生成也需要实际DeepSeek接口。没有“规则规划 / AI辅助”两种用户模式，规则仅在内部负责约束检查。

## 职责边界

DeepSeek只能从项目真实景点目录选择、分组和排序，不能生成新的酒店、餐厅或坐标。用户已确认的高德地点及日期保持原样。既有转场日不可插入景点，同片区分组、必去景点、徒步独立日和时长预算都需通过规则检查。

AI说明标注来源，并与已核实数据区分。当前无道路路径数据，所以不输出精确里程、车程、预计到达时间、实时票务或营业承诺。用户手动修改后再次检查，并标注AI说明来自修改前的版本。

服务器只向 `https://api.deepseek.com/chat/completions` 发送本次规划资料，密钥在服务端请求头中。浏览器仅调用本地 `/api/ai/plan`，不会接触DeepSeek API密钥。服务默认绑定127.0.0.1；`.env.local`、服务器源文件和点目录不能被静态下载。
