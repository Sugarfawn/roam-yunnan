# 第一阶段：真实交通参与每日可行性校验

更新：2026-11-11。保留首页、省域地图、目的地摄影与现有规划页布局。

## 本次解决的问题

此前 AI 安排与高德查询相互独立：每日预算只含固定交通预留，真实道路耗时只在卡片之间显示；酒店往返、餐厅接驳不完整参与负荷判断。界面中仍残留“无道路 API”等过时说明。

现在的流程是：AI 生成候选草案 → 浏览器查询全部日期的真实高德道路 → 合并游览、用餐、休息和交通预算 → 标出过满 / 偏紧 / 待核实 → 用户确认删减或改期建议 → 重新查询与核验。内部规则校验继续保留，用户仍只有一个 AI 生成入口。

## 核算与证据

- `traffic-feasibility.js`：纯数据核算、证据有效性、建议生成。统一使用 `RoamPersonalPlaces.sequence` 的景点、酒店起终点、餐厅和自选地点顺序。
- `traffic-service.js`：两个日期工作队列，沿用现有 POI 匹配和高德 Driving / Walking / Transfer 查询；取消后不提交过期结果。
- `planner-view.js`、`travel-planner.js`：每日核验摘要、全部日期的检查状态、交通方式覆盖、确认建议、保存恢复及编辑后的重新检查。
- 景点停留采用目录中的编辑估算范围。午餐每处预留 60 分钟，替代基础餐段；晚餐另计。休息沿用节奏配置，额外机动预留 30 分钟，均明确标记为编辑预留。
- 有有效交通证据时，真实交通替代旧固定交通预留，不重复累加 45 分钟“车程”。没有道路证据时，保留基础约束校验，页面只给参考状态。
- 当天可用预算继承旅行节奏、半日、抵达和离开时刻的既有约束。仅判定是否装得下，不生成虚假的精确到达时刻。
- 最低已知用时超过预算：过满；较宽松估算超过预算：偏紧；没有酒店、未知自选停留、未查路段、园内交通 / 徒步条件未知：不能标记为完整可安排。
- 道路来源、方式、查询时间、时长和距离保存在每日 `traffic`。只接受来源匹配、非负且有限的返回数据。缺失不写成 0，不用直线距离替代道路。
- 证据有效期 30 分钟；景点顺序、酒店、坐标绑定、日期窗口、节奏、交通方式变化后失效。刷新保留有效证据，当前日道路重新展示；页面恢复焦点、停留期间或用户点击可重新核验。

## 用户可操作的调整

- 过满 / 偏紧时，为非必去景点提供同地区同片区或空白日期的改期候选；必须通过原规则检查。
- “留到下次”仅移出当天，保留在待安排清单和已选心愿清单中。
- 必去景点和酒店不自动删除；无合适建议时提示增加天数或调整选择。
- 点击建议后才应用；更新受影响路段，重新核验。当前阶段不声称已按道路数据全局优化或完成 AI 局部重规划。
- 过满或其他硬冲突不能保存为已确认行程，草稿仍保留。信息不足的参考草稿可以保存，并明确标注未核实。
- 切换单段步行 / 自驾打车 / 公交会改变核算，覆盖选择持久化至 `settings.legModes`。

## 验证

在工作区根目录运行（仅开发期测试需要现有 `work/qa` 中的 Playwright）：

```text
node work/traffic-feasibility-check.cjs
node work/verify-traffic-experience.cjs
node work/travel-rules-check.cjs
node work/deepseek-check.cjs
node work/personal-places-check.cjs
```

第一项覆盖酒店往返、过满、未知路段、餐厅去重、半日窗口、失效、必去保护、改期、跨区、公共交通、保存恢复和取消。第二项用明确的模拟地图 SDK 与已录制 AI 响应走通实际页面，不冒充真实道路验证。原 360 组规则检查、模型接口契约与自选地点检查另行保留。

实际外部验证（需要联网和本地高德配置，不新增 DeepSeek 付费请求）：

```text
node work/check-live-traffic.cjs
node work/verify-traffic-live-flow.cjs
```

2026-11-11 实际查到大理古城到三塔的高德驾车道路；随后将真实搜索得到的测试酒店加入隔离浏览器的三日行程，验证全部日期交通计入、未知路段降级、保存恢复，浏览器无脚本错误。AI 为此前真实响应回放，本次不将其称为新的模型调用。

## 仍然存在的限制

POI 是地图参考位置，尚非经现场核实的开放入口；园内索道、排队、停车到入口步行、未来班次、预约、开放与天气仍需核实。未知自选地点停留时间不填虚构值。跨地区转场日仍单独留白，不据市内道路结果宣称完整可达。

本次未扩展目的地数据，没有增加聊天、预订、账户或后端数据库，也没有更新原参赛 ZIP；旧提交包仍是旧版本，确认这一阶段后需另行重新打包。
