# 自己安排、AI 规划与我的旅行

本次改动仅涉及规划模块，首页与云南省域地图的代码和视觉保留。

## 用户流程

- 从地图进入规划，创建旅行名称、可选出发日期和 1–4 天窗口，选择自己安排或 AI 帮我安排。
- 自己安排建立空白日期，不自动分配目录景点，不调用模型。添加地点到待安排清单后，选择日期放入行程；可调整顺序、改期、移回待安排或移除。支持用户填写每站起止时间、备注和当天备注。
- AI 沿用原有选点与设置页，生成前根据缺失信息显示同行者、步行强度、抵达窗口、雪山 / 徒步偏好等确认问题。每轮少量选项，可以返回或按已有信息生成。已回答字段不重复询问。
- 问题由前端明确规则选择，不伪装为模型对话；确认后的 aiProfile、天数、偏好、节奏、交通和抵离设置都进入真实 DeepSeek 请求。模型仍受目录、片区、必去和 JSON 校验限制，失败时旧计划保留。
- 两种方式共用每日行程和地图，可补充酒店餐厅、真实地图搜索与道路查询。AI 结果也可以手动填写时间、备注和调整地点。
- 手动计划可继续让 AI 编排，但本阶段是整趟旅行重新生成，操作前提示；生成成功前不覆盖旧路线，旧路线可在修改记录恢复。暂未实现聊天式局部 AI 重排或锁定指定日期。

## 存储与兼容

- 新增 roam.yunnan.journeys.v1，以独立 tripId 保存旅行的名称、模式、日期、设置、草稿 / 计划及更新时间。同一地区可以保存多趟旅行。
- URL 中 trip 参数恢复指定旅行；旧地区计划与第三版 ID 迁移继续保留。
- 用户显式编辑或重新生成前保存最近 10 个版本，恢复前也保留当前状态；历史快照不保留过期交通证据。路线查询 / 切换日期的自动刷新不作为用户修改生成快照。
- 支持查看、继续、导出 JSON 和确认删除。删除当前旅行同时停止异步核验并清理地区缓存，避免刷新后重新出现。
- 存储写入失败不替换已有旅行记录，页面提示并保留内存编辑，可导出。没有云同步与账号；清除浏览器数据会清除本地旅行。

## 时间与交通

起止时间明确标为“我的安排”，不是 AI 保证的到达时间或已预约时段。保存时检查开始 / 结束完整性、非跨夜、列表时间顺序与重叠；已查道路小于预留时会提醒。只写顺序不填时间也可以保存。

用户设置的目录景点停留时间参与当天预算；没有填写时沿用明确标记的编辑估算。缺失道路、景区内部接驳、索道和未知自选地点停留仍需确认，不通过直线推算精确车程。

## 视觉与验证

规划区域增加摄影背景、半透明米白玻璃、细线与暖金；桌面结果区域固定在窗口，日期和操作保持可见，日程、待安排与地图在各自区域滚动。手机自然排版。

运行 npm test、npm run test:journeys、npm run test:browser、npm run test:integration。新测试覆盖空白手动计划、多旅行、用户时间、冲突、改期、删天、待安排、历史恢复、存储配额、AI 问答与失败保护。浏览器验证使用录制响应和明确的离线地图替身，不消耗模型余额，也不将样本截图当真实道路结果。
